# Compétences et retour d'expérience

## Compétences techniques mobilisées

- audit de sécurité web et API ;
- raisonnement sur les autorisations objet et les rôles ;
- analyse de réponses HTTP et de jetons d'authentification ;
- tests négatifs et tests de non-régression ;
- analyse statique, analyse de dépendances et détection de secrets ;
- automatisation Bash et traitement de spécifications API ;
- orchestration d'environnements conteneurisés ;
- conception et diagnostic de pipelines CI/CD ;
- qualification des faux positifs et erreurs d'environnement.

## Compétences organisationnelles

- cadrage d'une mission de sécurité dans un délai limité ;
- priorisation par risque ;
- constitution de preuves reproductibles ;
- séparation entre données publiques et confidentielles ;
- documentation des décisions et risques résiduels ;
- communication de résultats techniques à différents interlocuteurs.

## Enseignements principaux

1. Un contrôle de sécurité doit être placé au niveau où la décision est prise,
   et non uniquement dans l'interface.
2. Une preuve technique doit démontrer l'impact et la persistance, pas seulement
   une réponse favorable.
3. Une pipeline verte n'a de valeur que si son périmètre et ses règles sont
   vérifiés.
4. La sécurité automatisée complète la revue humaine sans la remplacer.
5. Les scénarios métier sont indispensables pour couvrir les défauts
   d'autorisation que les scanners génériques comprennent difficilement.
6. La confidentialité fait partie intégrante du cycle de documentation.
